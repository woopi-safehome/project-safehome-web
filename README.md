# SafeHome Web

등기부등본 분석 서비스의 **웹 프론트** (Next.js App Router).
로그인 없이 분석할 수 있고, 로그인하면 분석 이력이 남는다.

> **범위**: `project-safehome-web/**`
> **여기 없는 것**: 컴포넌트·함수 이름과 라이브러리 버전 — 코드와 `package.json` 이 답한다.
> 서버 응답 형식도 여기 없다. 원본은 api 저장소가 갖는다.

---

## 실행

```bash
npm install
npm run dev      # 개발 서버 (http://localhost:3000)
```

## 검증

```bash
bash scripts/verify.sh    # lint · test · build 를 한 번에
```

**CI 가 이 파일을 그대로 실행한다** — `develop` 으로의 push 와 pull request 에서 돈다.
다른 명령으로 대신하면 로컬 통과가 CI 통과를 뜻하지 않는다.
**의존성 설치는 이 파일이 하지 않는다** — CI 는 잠금 파일 그대로 받는 명령을 따로 쓰고,
그 명령은 받아 둔 것을 지우고 다시 받으므로 개발 중에 매번 돌리기에는 무겁다.

셋이 **보는 것이 다르다.** 하나만 돌리면 나머지가 깨진 걸 모른다.

| | 무엇을 보나 | 못 보는 것 |
|---|---|---|
| `lint` | 의존 방향 위반 | 타입, 동작 |
| `test` | 동작 | 구조, 타입 |
| `build` | 타입과 정적 생성 | 의존 방향 |

테스트는 Vitest 로 돌린다. `async` 서버 컴포넌트는 단위 테스트가 지원되지 않으므로 E2E 로 다뤄야 한다.

**셋 중 어느 것도 브라우저에서 실제로 그려지는 것은 보지 못한다.** 단위 테스트에는 CSS 가 적용되지 않아
**초점이 갈 수 있는지, 글꼴이 실제로 쓰이는지, 배색이 읽히는지가 전부 통과한 채로 지나간다.**
실제로 `display:none` 으로 감춰 **키보드로는 파일을 고를 수 없는 입력**이 모든 검증을 통과한 적이 있다.
화면을 건드렸으면 **띄워서 눈으로 본다.** 이건 자동으로 걸리지 않는다.

## 구조

```
src/
├── app/        라우팅과 조립만 한다. 화면 로직을 두지 않는다
├── features/   기능 하나가 폴더 하나. 그 기능의 컴포넌트·상태·서버 호출을 함께 둔다
└── shared/     기능들이 함께 쓰는 것 — 서버 통신, 설정, 공용 UI
```

**의존은 `app → features → shared` 한 방향뿐이다.**

- `shared` 는 `features`·`app` 을 모른다
- 기능끼리 가로로 참조하지 않는다 — 같은 기능 안은 상대경로, 기능 사이에 공유할 것은 `shared` 로 올린다

**이 규칙은 ESLint 가 막는다.** 어기면 lint 가 이유와 함께 실패하므로 외울 필요가 없다.
규칙을 바꾸려면 `eslint.config.mjs` 의 경계 설정을 고친다.

## 서버 통신

**모든 서버 호출은 `shared/api` 한 곳을 지난다.** 화면에서 직접 `fetch` 하지 않는다 —
흩어지면 인증·봉투 처리가 제각각이 되고 계약이 바뀔 때 빠뜨리는 곳이 생긴다.

**엔드포인트 스펙의 원본은 api 저장소 README 의 계약 절이다.** 이쪽에서 형식을 정하지 않는다.
모르는 필드가 와도 무시하고 동작해야 한다 — 서버가 이 앱보다 먼저 배포된다.

**회원 인증은 `Authorization: Bearer` 헤더, 비회원의 주인은 쿠키다.**
토큰은 직접 들고 있다가 매 요청에 붙인다. 익명 쿠키는 서버가 발급하고 스크립트가 읽지 못하므로(`HttpOnly`)
**이쪽에서 꺼내 붙일 수 없고, 브라우저가 알아서 싣도록 같은 출처로 보내야 한다.**

**그래서 브라우저는 이 앱하고만 통신하고, `/api/*` 는 이 앱이 백엔드로 넘긴다**(`next.config.ts`).
백엔드를 직접 부르면 교차 출처가 되어 쿠키가 빠지고, **비회원이 자기 결과를 못 보게 된다.**
넘길 주소는 서버에서만 읽는 값이라 브라우저에 내려가지 않는다.

> ⚠️ **이 앱을 가장 바깥에 두면 백엔드가 모든 사용자를 한 주소로 본다.**
> 넘길 때 원래 요청자의 주소 헤더를 **만들어 붙이지는 않기 때문이다**(들어온 것은 그대로 통과시킨다).
> 백엔드는 그 주소로 비회원 사용량을 세므로, 앞에 그 헤더를 붙이는 프록시가 없으면
> **비회원 전체가 한 주소의 한도를 나눠 쓰게 된다.** 배포할 때 함께 봐야 한다.

**401 이면 한 번만 토큰을 갱신하고 다시 보낸다.** 갱신을 서버가 거절하면 토큰을 지우지만,
**네트워크 오류에서는 지우지 않는다** — 잠깐 끊긴 것으로 로그인 상태를 날리면 사용자는 이유 없이 로그아웃된다.

**진행 상황 구독에 `EventSource` 를 쓸 수 없다.** 헤더를 붙이지 못해 인증이 실리지 않는다.
fetch 로 열고 본문 스트림을 직접 읽는다.

**비회원은 토큰이 없으니 헤더도 붙지 않는다.** 이쪽에서 따로 분기하지 않는다 —
서버가 헤더 없는 요청을 비회원으로 받는다. 업로드·진행 구독·결과 조회가 그렇게 열려 있다.

> **비회원의 결과는 업로드한 브라우저만 볼 수 있다.** 서버가 발급한 익명 쿠키가 주인이라,
> **링크를 넘겨도 결과는 따라가지 않는다** — 등기부에는 주소와 소유자 이름이 들어 있기 때문이다.
> 쿠키를 지우거나 다른 브라우저로 옮기면 자기 분석도 다시 볼 수 없다.
> 조건을 정한 것은 서버이므로 근거는 api 저장소의 계약 절이 갖는다.

**회원은 하루에 시작할 수 있는 분석 수가 정해져 있다.** 넘기면 서버가 거절하므로
화면은 그 문구를 그대로 보여주고, **다시 눌러도 같다는 것**과 언제 풀리는지를 덧붙인다.
횟수와 기준은 서버가 정한다 — 이쪽에서 세거나 미리 막지 않는다.

**식별자를 잃으면 비회원은 결과를 다시 찾을 수 없다.** 이력 목록은 로그인해야 나온다.

> **이건 결정이지 빠진 기능이 아니다.** 익명 쿠키로 목록을 묶어 보여 줄 수도 있지만,
> **그렇게 하지 않기로 했다** — 이력을 원하면 로그인하는 것이 이 서비스의 선이다.
> 쿠키는 지워지고 기기 사이를 넘지 못해 이력이라 부를 만큼 남지도 않는다.
> 대신 **결과가 남지 않는다는 사실을 화면에서 먼저 알린다.** 닫은 뒤에 알게 되면 안 되기 때문이다.

## 분석 진행 화면 — 이 앱에서 가장 복잡한 곳

```
구독 시작 → 단계 이벤트 수신 → (완료 수신) → 결과 조회 → 완료
```

**완료 이벤트가 결과를 담고 있지 않다.** 완료를 받으면 결과를 **따로 조회해야** 한다.
두 단계를 하나로 착각하면 결과가 비어 보인다.

**각 단계를 최소 시간만큼 붙잡아 둔다.** 전환이 너무 빠르면 사용자가 무엇이 일어났는지 인지하지 못하고
화면이 깜빡이며 넘어간다. **이 지연은 의도된 것이다** — 진행이 느려 보인다고 지우면 그 증상이 돌아온다.
서버가 실제로 걸린 시간과 화면 표시가 어긋나는 이유이기도 하다.

**끝나는 경우가 셋이다.** 정상 완료, 실패 이벤트, **스트림의 비정상 종료.**
셋 다 테스트가 잡는다. 세 번째를 빼먹으면 연결이 끊겼을 때 **화면이 영원히 진행 중으로 남는다.**
그래서 재시도 경로를 둔다.

## 결과 화면

**결과의 구조는 api 가 아니라 ai-api 가 정한다.** 백엔드는 해석하지 않고 그대로 통과시키므로,
형식이 의심스러우면 ai-api 저장소의 계약 절을 본다.

**등기부등본이 아닐 수 있다.** 그 경우 판정 자체를 건너뛰고 이유만 오므로, 나머지 필드의 존재를 가정하면 깨진다.

**없을 수 있는 필드가 셋이다.** 있으면 보여주고 없으면 그 자리를 비운다 — 목록과 조건은 ai-api 계약 절에 있다.
그중 하나는 **등급만 보고 존재를 단정할 수 없다.** 조건이 등급 하나가 아니기 때문이다.

**결과는 이 화면에서 다시 조회한다.** 앞 화면이 들고 있던 값을 넘겨받는 구조로 만들면
주소로 바로 들어오거나 새로고침했을 때 빈 화면이 된다.

## 로그인

> **카카오 토큰을 얻는 한 곳만 비어 있다.** 로그인 화면도, 서버에 넘겨 이 서비스의 토큰으로 바꾸는 쪽도 있다.
> 키가 없으면 **로그인 화면이 버튼을 잠그고 그 사실을 알린다** — 눌리는데 아무 일도 안 일어나는 버튼을 두지 않는다.
> 채우는 데 무엇이 필요한지는 그 자리의 주석이 갖는다.

**어느 SDK 흐름을 쓸지 미리 적어 두지 않았다.** 버전에 따라 쓸 수 있는 방식이 달라서,
키가 생긴 뒤 문서를 보고 정한다. 기억으로 적어 두면 틀린 코드가 남는다.

**처음 온 사람만 소개 화면을 거친다.** 신규 여부는 서버가 로그인 응답으로 알려 준다.

**로그인 여부는 토큰이 있는지로만 판단한다.** 유효한지는 확인하지 않는다 —
만료된 토큰은 서버가 401 로 답하고 통신 계층이 갱신을 시도한다.
화면이 미리 확인하려 들면 서버와 판단이 갈라지고, 확인하는 동안 화면이 멈춘다.

**저장소는 바뀐 것을 스스로 알려 주지 않는다.** 그래서 토큰을 쓰고 지우는 곳에서 직접 알린다.
빠뜨리면 로그아웃해도 화면이 그대로 남는다. 다른 탭의 변경도 같은 통로로 들어온다.

**회원 탈퇴는 서버가 지운 뒤에 토큰을 버린다.** 먼저 버리면 요청을 보낼 인증 수단이 사라져
실패했을 때 다시 시도할 수 없다.

## 이력 목록

**요청의 페이지 번호는 0부터, 응답의 현재 페이지는 1부터다.** 기준이 다르므로 응답 값을 그대로
다음 요청에 넣으면 한 쪽을 건너뛴다. 다음 쪽이 있는지는 별도 필드로 본다.

**더 불러오기가 실패해도 이미 있는 목록을 지우지 않는다.** 보고 있던 것이 사라지기 때문이다.
번호도 **성공한 쪽까지만 올린다** — 실패한 시도로 밀리면 한 쪽이 통째로 빠진다.
첫 조회의 실패만 화면 전체의 오류로 다룬다.

**날짜는 문자열에서 잘라 쓴다.** 서버가 오프셋 없는 시각을 주므로 파싱하면 브라우저 시간대로
해석되어 하루가 밀릴 수 있다.

## 환경 변수

브라우저까지 내려가는 값이므로 **전부 공개된 것으로 다룬다.** 서버 비밀값을 두지 않는다.

| 변수 | 언제 읽히나 | 쓰임 |
|---|---|---|
| `API_ORIGIN` | **빌드 시점** | `/api/*` 를 넘길 백엔드 주소. 로컬 전용이다 — 배포에서는 앞단 프록시가 넘긴다 |
| `NEXT_PUBLIC_API_URL` | **빌드 시점** | 비워 두는 것이 기본. 값을 넣으면 브라우저가 백엔드를 직접 불러 **쿠키가 빠진다** |
| `NEXT_PUBLIC_KAKAO_JS_KEY` | **빌드 시점** | 카카오 JavaScript 키. 없으면 로그인 버튼이 잠긴다 |

**셋 다 실행할 때 바꿀 수 없다.** `NEXT_PUBLIC_` 값은 브라우저 번들에 박히고,
`API_ORIGIN` 은 `next build` 가 `routes-manifest.json` 에 써 넣는다.
**컨테이너 환경변수에 넣어도 아무 일도 일어나지 않는다** — 값이 바뀌면 이미지를 다시 만든다.

## 배포

`develop` 으로 push 하면 [`deploy-web-dev.yml`](.github/workflows/deploy-web-dev.yml) 이 돈다.
**검증 → 이미지 빌드 → 기동 확인 → push → 서버 교체** 순이고, 앞 단계가 실패하면 뒤로 넘어가지 않는다.

| 무엇이 막히나 | 어디서 |
|---|---|
| lint · test · 타입 | `verify` 잡 (`scripts/verify.sh`) |
| **이미지가 뜨지 못하는 것** | `build-and-push` 의 기동 확인 — 검증은 이미지를 보지 않는다 |
| **기동 실패한 배포가 초록으로 지나가는 것** | `deploy` 의 헬스 체크 대기 |

### 이 앱이 놓이는 자리

```
브라우저 ──▶ nginx (safehome.devupii.store)
                ├─ /api/  ──▶ API        :8080
                └─ /      ──▶ 이 앱       :3000
```

**`/api/` 는 이 앱을 거치지 않는다.** 앞단이 바로 API 로 보낸다.
그래야 진행 상황 스트림(SSE)이 중간 단계를 덜 지나고, 빌드 시점에 박히는 `API_ORIGIN` 에
배포가 묶이지 않는다. 대신 **웹과 API 가 같은 출처**라, 비회원 분석의 주인을 가리는
쿠키(`Secure`·`path=/api`)가 그대로 실린다. 이 배치가 깨지면 **에러 없이** 업로드한 사람이
자기 결과를 못 보게 된다.

nginx 설정의 원본은 [`docker/dev/nginx/safehome.conf`](docker/dev/nginx/safehome.conf) 다.
서버의 `/etc/nginx/sites-available/safehome` 은 사본이므로 **서버에서만 고치지 않는다.**

### 서버에 처음 올릴 때

저장소 밖에서 한 번만 해야 하는 것들이다.

1. **DNS 레코드.** 이 도메인의 다른 호스트와 같은 모양으로 만든다 —
   **DDNS 이름을 가리키는 CNAME** 이다. IP 를 직접 적는 A 레코드로 만들면
   공인 IP 가 바뀌는 날 이 호스트만 죽는다. 와일드카드가 없어 호스트마다 하나씩 필요하다.
2. nginx 설정 배치 후 `sudo certbot --nginx -d safehome.devupii.store`
3. `/home/woopi/project/safehome/env/.env_web` 에 `GITHUB_OWNER=` 한 줄
